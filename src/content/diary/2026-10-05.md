The Activity panel on a manual turned out not to be an activity log at all. It was three model fields, created_at, submitted_at and reviewed_at, dressed up as a timeline, so a document that had only been edited showed nothing but Document created. It reads the real log now, with an auditor endpoint built on the same pieces so the two cannot drift apart, and a second call once the list passes ten entries.

The client proposed how Corrective Action records should behave. I went back on whether his proposal solves the problem he described, and it comes off the manual document itself with no extra status: open or closed follows auditor approval rather than document status, the generated file never prints a version, and an auditor approving one now sees every field, with the ones that are not theirs disabled.

Policy templates took the rest of the day. The ask arrived big and came down to picking a template, downloading it, editing it and uploading the file back, with the annex options following whichever framework the admin picked. It stopped on a migration that had never been generated, so the admin page died on a table that does not exist. Michael also cut Policy Document as a document type, since PMS already covers policy creation and lifecycle, so nothing gets built there.

Six merged by the end: the timeline, corrective actions, evidence logs showing filenames instead of document uuids, framework required when a policy is created, and long revision reasons wrapping inside 60% rather than stretching the popover.
