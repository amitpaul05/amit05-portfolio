Today I was fully busy with one of our e-commerce app "Shikago". There was a problem in Oscar, it doesn't allow partners(sellers) to add products with multiple variants(size, colours, etc). I found the main problem is that Oscar has this permission scoped only to admins. Resolved this problem from both view and template level.

Then found another problem, Before creating any variants, the parent product must be created, but as the parent product does not have anything to point at the partner(as owner), it was filtered out from product list for that partner. So I assigned a partner (owner) with the parent product, which will be auto-assigned.

Then found a case, as multiple developer is working on the backend, any migration can cause a db break in the dev server. So I added a functionality to check before every migration, it anything to apply it will create a backup. Also added skips and validation if no volume is defined in the docker compose, so that containers are free from carrying a db backup which will be vanished after a rebuild.

Also debugged a problem in Oscar, when a user creates any order with multiple product from multiple seller in a single product, both the seller can change the full order status. I refactored it product-specific, and the full status to be auto-changing or admin-controlled.
