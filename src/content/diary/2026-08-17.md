A company_admin account kept getting a 403 on our new documents API while the same token worked on every other endpoint. The account was fine and so were the migrations, because a superuser could upload without trouble. Every API we added before this one was a new endpoint on an existing model, so its group permissions were already in place. This time it was a whole new app, so migrate created fresh permission rows and nothing ever attached them to a group.

Curl settled it: documents came back 403 while manuals, answers and audits returned 200 on the same token. The real bug lived in our deploy script, which runs migrations on each release and nothing else, so the permission command had not run since someone last did it by hand. All four environments share that script, so I checked the blast radius before touching it, then added the command to the same gateer release and fails thedeploy loudly instead of crash-looping a live service.
